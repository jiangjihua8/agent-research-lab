# 适用于哪些 AI 研究，怎样接入

这是**实验型人工智能研究的共用流程与执行框架**。它统一问题、证据、预算和决策，不预置某个领域的创新答案。时间序列只是一个示例；LLM、优化器、视觉、多模态、强化学习和推理系统也可接入。

可复用的是查新、假设反驳、环境验收、公平对照、逐轮实验、确认和复现。不可直接复用的是数据切分、主指标、独立统计单位、训练实现与机制诊断。纯理论证明、湿实验、临床研究或需要复杂自适应试验的项目，需要另行扩展，不能硬套模型×数据×种子的默认网格。

## 按课题选择实验约定

| 方向 | 最先校准的条件 | 必须区分的解释 | 常见机制读数与成本 |
| --- | --- | --- | --- |
| LLM 预训练／记忆／注意力 | tokenizer、语料版本、去重、有效 token 数、上下文长度和预测掩码 | 数据量、训练更久、可见信息、容量与记忆机制 | 按距离／干扰分组的读数，通用语言建模损失，训练计算、吞吐、显存 |
| 优化器（包括 Muon） | 相同初始化与数据顺序、参数分组、精度、batch、学习率日程 | 单步更贵、学习率欠调、特殊参数由另一优化器更新 | 损失对 token／步数与墙钟两组曲线，更新范数、稳定性、到达目标质量的成本 |
| 视觉／检测／分割 | 样本与场景切分、分辨率、增广、预训练权重、标注口径 | 高分辨率、更大骨干、外部数据与所提机制 | 目标尺度／遮挡子群、定位错误、任务指标、实际延迟和内存 |
| 多模态／融合 | 同一实例跨模态配对、缺失模态、训练与推理时可得信息 | 单模态已足够、额外标签、跨切分近重复 | 单模态对照、模态打乱／缺失曲线、对齐诊断、输入与计算成本 |
| 时序／预测 | 时间顺序、窗口重叠、归一化和未来协变量 | 泄漏、季节性简单基线、不同预测跨度 | 按跨度／频率／漂移分组误差，跨实体泛化、滚动评测成本 |
| RL／决策 | 环境版本、奖励、交互步数、训练种子和独立评估回合 | 奖励捷径、额外交互、更高搜索预算 | 回报分布、成功率、学习曲线、环境步与计算开销 |
| 推理加速／量化／系统 | 同硬件、软件版本、输入分布、并发与质量容差 | 精度下降换速度、缓存／编译、不同 batch 或长度 | 质量—延迟—内存权衡，预热后分位延迟、吞吐与端到端时间 |

不要把表中所有指标都列成主指标。按问题预先指定主读数、诊断读数和约束；有权衡就分别呈现。RL 的多个回合不等于多个独立训练种子，语言模型的 token 也不能自动当作独立重复。

## 接入已有研究代码

1. 创建独立研究目录。先读现有代码、数据、机器和约束，选择表中相关一行；将具体决定记入 `inputs/domain-brief.md` 的副本。
2. 保留现有训练器，用一个薄适配脚本接入 `execute`；或继续用集群运行并 `record`。不为接框架而重写模型。
3. 适配器真正读取 `RESEARCH_SEED`、模型与数据 ID、`RESEARCH_EVALUATION_SPLIT`，输出到 `RESEARCH_OUTPUT_DIR/metrics.json`。输出必须来自实际计算；额外逐样本预测、checkpoint、曲线保存到同目录。
4. 在协议登记训练代码、配置、环境、切分和评测；具体接口见 [execution.md](execution.md)。环境变量只是传入约定，框架不会自动替训练器设置随机种子、切数据或限制显存。
5. 先跑真实路径的微型 smoke，再运行基线 pilot 与评测有效性检查。通过后才正式登记候选与自动搜索。

没有现成代码时，Agent 根据已核实论文实现最小可复现基线；需要数据和依赖时按已有授权准备。框架自身只用 Python 标准库，真实训练可在独立环境使用 PyTorch、JAX 等。不要因框架能检查 JSON 就认为领域实现已被验证。

## 用户怎样开始

用户给出大方向即可先检索和拆问题。开始实际训练前，至少要确定：一个具体问题、可用数据／代码、机器与总预算。预算未知时仍可做查新和准备；默认 0 GPU 不等于已有 GPU 研究预算。

可直接说：“重点研究优化器，先读 Muon 相关工作和我的训练代码；把问题缩到当前算力能检验的机制差异，先跑基线，提出两个竞争解释并做最小判别实验。”这会产生待验证的研究，不会预设某个改动必然有效。

项目提供本地执行与证据管理，不调用外部模型 API，也不替代训练集群。选择不同领域通常只改研究目录的材料和适配器；不需要改变框架的创新流程。

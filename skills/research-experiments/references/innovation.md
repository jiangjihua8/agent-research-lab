# 创新：让每轮实验改变一个判断

本流程主要吸收素材②的材料拆解与可证伪假设、④的模块功能分析、⑤的可信环境内探索，并结合后来核对的 Vuk 系列中讨论、事前预测与结果复盘的方法。选题与点子辩论见 [research-ideation](../../research-ideation/SKILL.md)。①③的写作规则不参与本流程。

## 先建立失效，而不是先给模块起名

完成基线验收后，沿样本子群、输入长度、噪声、分布变化、训练稳定性、记忆或计算成本检查表现。先用验证集和诊断材料回答：

- 失效在什么条件下稳定出现，影响多少实际样本？
- 简单调参、训练更充分、修复数据或评测能否消除它？
- 强近邻方法是否已经解决？若是，尚未解决的代价、范围或机制问题是什么？

保存失败样本、分组指标、学习曲线或信息流诊断到 artifacts。**实现错误**先修，**基线欠调参**先补，**真实且重要的能力缺口**才进入创新提案。一次偶然的低分不够。

没有本地观察时，可从已核实论文定义待验证问题；在提案中说明证据来自文献，先复现失效。初始 hypothesis.json 是待检验判断，不是已经成立的发现。

## 把文献变成机制地图

每篇论文不是一段摘要，而是一行“失效条件 → 原因假设 → 改变的信息流 → 关键证据 → 成立前提”。方法迁移前补出输入、输出、状态、训练信号、成本和依赖假设。

例如，视频模块的收益可能来自时间连续性。迁到无序样本时应先检验这个前提；不能因为模块名含 attention 就认为能直接迁移。优先借用处理问题的原理，再决定实现是否需要那个模块。

检索需覆盖任务词、问题别名、机制词、最邻近方法、引用及被引工作，并主动找失败复现和反例。登记原始来源和检索日期；AI 记忆中的“好像没人做过”不能当查新结果。

## 一份提案只检验一个核心解释

复制 `inputs/idea.json`，填写并用 `propose` 固化。先保留少量能在预算内判别的候选，不批量生成几十个模块名字。

| 字段 | 决策所需内容 |
| --- | --- |
| failure + artifacts | 哪个基线在什么条件失效，日志或文献位置在哪里 |
| mechanism | 一个可被反驳的原因，不重复描述症状 |
| intervention | 最小干预，具体改变哪一段信息流 |
| prediction | 如果原因正确，主指标以外还会出现什么可测变化 |
| falsifier | 看到什么结果就放弃该解释，或改变研究方向 |
| alternatives | 容量、计算、调参、数据、随机性等竞争解释 |
| paper_ids + novelty | 最接近工作已经做了什么；本提案新增了什么可检验认识 |
| minimal_test | 对照组、读数、支持条件、停止条件、预计成本 |

少量候选同时保留是为了比较不同解释。研究预算允许时可从 2–3 个候选起步；这不是科学门槛。预留正式确认和失败重试的资源，不能把全部预算花在验证集搜索。

## 最小判别实验的设计

先选择最有可能排除错误解释、又最省资源的一项实验。不要为每个想法立即跑全数据集、全种子和长训练。

| 观察与解释假设 | 最小干预和必要对照 | 诊断读数 | 什么会削弱解释 |
| --- | --- | --- | --- |
| 长间隔检索变差，怀疑状态覆盖 | 保留/移除记忆，匹配容量的无记忆基线 | 按间隔与干扰项分组的验证准确率、状态保留诊断 | 增大普通模型容量即可解释收益；间隔诊断不变 |
| 小目标漏检，怀疑下采样损失 | 一处保留细节；与等成本宽化对照 | 小目标 AP、定位错误和高分辨率特征响应 | 所有尺度同比改善且机制诊断不变 |
| 多模态模型偏向单模态 | 控制缺失/冲突信息；加入单模态对照 | 模态扰动曲线、错误类型、数据分组 | 收益只来自额外标签或不可用的输入 |
| 长序列预测受相位变化影响 | 只改变对齐机制；无对齐容量对照 | 按相位偏移分桶误差、对齐量诊断 | 非相位因素解释收益；破坏对齐后不变 |
| 候选收益很小，怀疑随机性 | 固定配置，补独立重复或配对比较 | 效果量、方差和独立单位 | 波动覆盖观察差异，缺乏实际价值 |

这些是实验设计示例，未断言现象已存在，也未给出真实结果。诊断图同样需要机制合理性，注意力热图本身不能证明因果。

## 模块组合怎样成为有价值的贡献

④中可采用的是“跑通 baseline、拆功能、找可迁移原理、针对领域适配”。组合本身可以值得研究，但至少解释：

1. 两种原理为什么互补，哪些前提让组合成立？
2. 哪部分已有、哪部分修改、哪部分认识由本研究新增？
3. 简单拼接、单模块、等容量替代能否得到同样结果？
4. 什么条件组合无效，新增成本是否值得？

若只是把 A 换成 B、性能持平、没有新的机制或用途认识，不能将其升级为已成立的创新。若性能相近但显著减少实际成本，或揭示此前不清楚的失效规律，则根据真实证据评价该贡献。

近邻对照至少列“问题、假设、方法、数据、资源、结果适用范围、新认识”。不要用名字不同或比参数表更长证明新颖性。

## 每轮固定输出：执行事实 → 解释 → 决策

读原始日志、所有同轮运行和诊断图后，先判断执行是否正确，再判断假设是否得到支持。使用 `inputs/decision.json` 和 `decide` 保存决策，不能只在聊天中口头决定。

| action | 什么时候用 | 下一项动作 |
| --- | --- | --- |
| continue | 实现通过但还缺能区分解释的证据 | 跑一个具体对照或增加与问题相称的训练保真度 |
| revise | 某前提被否定，仍有可检验的新解释 | 保留原提案；新建 id，修改假设并重新冻结受影响协议 |
| drop | 重要性、重合度、证据成本或实验结果不支持继续 | 保存失败或负结果、终止该候选的计算 |
| promote | 验证集证据支持进一步确认，机制和混杂对照值得扩大 | 固定实现与配置，安排独立测试和正式网格 |

程序要求 promote 引用当前协议下各基线与候选的 validation pilot，不能只给 smoke；它不自动比较分数宣布创新成立。解释是否充分、是否值得扩大由研究判断决定。已运行失败可以决定 drop，但失败只说明实现或可行性问题，不能直接证明科学假设错误。

记录同一想法的所有轮次，包含试过的超参数和没有选中的版本。若看过 test 才改变假设，必须说明受测试启发，并规划新的独立确认；换一个 protocol hash 不能消除数据污染。

## 什么时候扩到长实验

扩算力前逐项回答：基线是否可信；短测和小样本测试是否正确；验证信号是否稳定；机制诊断是否相符；最简单的替代解释是否被排除；完整证据成本是否承担得起。

回答不足时，补最有信息量的一项对照。回答足够时，写清正式实验网格及冻结选择规则。遇到小模型与大模型、短训练与充分训练排名可能反转的问题，使用学习曲线或有代表性的尺度探针，而不是机械按五分钟成绩淘汰。

不存在 ICML 通用的“至少 100M 参数”门槛。规模应覆盖主张：声称可扩展就需要相应规模证据，资源不足就收窄实际研究问题。

## 结束一次研究循环

完成对候选的 continue/revise/drop/promote 决策和消耗核对，更新 STATE.md。连续若干轮没有新信息、达到预算上限、已被近邻覆盖、关键评测错误无法修复，均应停止或转向。次数与资源由项目约定，不能无限“审到无问题”或“搜索到赢”。

正式实验完成后把发现、范围、反例和原始证据交给写作阶段。写作阶段的补实验请求只是一项待评估问题，不拥有实验决策权。

# 自动探索、尺度晋级与意外结果

在基线与评测验收后使用。本流程适用于明确资源边界内的实验，不把“永久自主运行”当作默认目标。

## 运行前写预测，运行后解释偏差

使用 `inputs/experiment-intent.md` 记录本轮的竞争解释、各自预测、判别读数与决定规则。在 job 添加 `intent_file` 路径，`execute` 启动进程前复制归档，结束后与运行证据一并保存。之后更改工作副本不改变已保存预测；这是本地可追溯记录，不是第三方时间戳认证。

预测可给方向、范围或几个可能结果。没有依据时写未知，不编造小数。运行后把实测与原预测并列：首先核实是否跑对，接着排除训练不足或测量噪声，最后再评价机制。意外结果应产生一个新的可区分问题，不立即改模型来追高分。

例如，“候选提高正确率”不足以检验机制；若解释涉及远距记忆，需要预先说明距目标更远、干扰更多时的预期变化，以及等容量或简单检索对照会怎样表现。

## 微型检查和预算梯度

设定每级数据量、训练步数、模型规模、指标和晋级依据。秒数只是成本估计；等时、等数据、等步数是不同对照条件，按问题选择。先用同一路径 smoke 查错，再用 pilot 观察机制，最后才进入正式确认。

短预算排名不可靠时，不能自动早停输在起步阶段的方法。用少量**基线与代表性方案**跨预算做探针，检查曲线、排名反转和效应方向；必要时逐个改变训练长度、规模、数据，避免同时改变后无法解释。极少模型的排序一致也不能保证新候选可外推。

如果小尺度无法保留目标现象，就提高最低有效预算或缩小研究问题。不要强迫所有现象在五秒内出现。真实任务、机制诊断和目标规模应覆盖最终主张；最大可负担规模本身不保证覆盖主张。

扩大前检查实际峰值显存、磁盘、checkpoint 恢复、每步成本及完整确认预算。多个预先指定的种子／数据集共同构成最终确认，独立测试不是“只能运行一个种子”；关键是结果不能反馈到选择过程。

## 防止搜索空转

每轮先看 `next`、历史提案和 DECISIONS.md，将尝试归到“机制、假设、干预、配置和预期读数”。同义改名或重复学习率不构成新方向。明确当前是在做调参，还是检验机制；前者的增益不自动成为后者的创新证据。

一轮只改一个核心解释相关因素；必要的多因素设计要预先写明对照结构。计划批量任务可顺序执行，但遇到需要解释的新结果先停下做决定，不跨关口盲目跑完整队列。重复次数和停止阈值由研究预算约定，不固定为 50 个实验或无限循环。

长会话恢复时保存问题、冻结版本、已尝试方向、原始运行、未解决问题和下一步命令，通过 STATE.md 与 `next` 交接。区分科学上停止、缺资源、等待作业与程序崩溃；完成目标或达到预算是合理终止，不应由“守护 Agent”自动无限重启。

本项目默认单 Agent 和顺序执行器；没有部署多 Agent、守护服务、定时调度或远程训练。需要这些能力时，另按用户实际环境接入，并保留同一证据和预算规则。

# 根据证据写作与准备投稿

输入是实验阶段交付的证据。此技能不编辑实验协议、运行记录或研究决策；需要补实验时形成问题单，交回 research-experiments。写作规则不得作为筛选实验和删除负结果的依据。

## 先建主张账本

从研究问题和正式结果建立 claims.json，不先编摘要再补实验。每个准备写入论文的主张标注：支持强度、适用条件、真实限制、位置、正式运行 id、文献 id 和分析文件。

- `supported`：当前证据足以支持该范围内的表述。
- `qualified`：限定条件后成立，正文必须显式保留该条件。
- `unsupported / rejected`：保留研究记录，`included_in_paper=false`；若要报告假设被推翻，应把“观察到的负结果”另立为有证据的主张。

经验性能主张引用正式运行；机制主张还引用针对该机制的消融与替代解释分析；相关工作主张引用已核查原文。表和图应由保存的原始指标或其派生分析生成，注明协议、数据、n 和统计量定义。不得手工改数。

工具只核对引用和证据存在，不会理解一句话是否夸大。作者与审查者仍需逐句核对，包括摘要、标题、图注中的“首次”“普遍”“显著”“因果”“SOTA”。

## 组织正文

正文初稿放在 paper/manuscript.md；其 Markdown 引用用 `[@P001]`，与 literature.json 的 id 和 references.bib 的 key 一致。

引言交代实际问题、现有解释的缺口、工作假设及经过验证的贡献。方法说明来源、输入输出、信息流和计算代价。实验从协议与强基线出发，陈述核心结果、诊断、反例和成本。结论回答问题，并保持与已测范围一致。探索日志和失败实现可以放决策记录，不必挤进摘要。

正式投稿前采用目标年份、track 的官方模板，将经审阅的内容和图表迁移到 LaTeX 或其他要求的格式。更新交叉引用、补充材料、作者信息与匿名设置。CLI 检查 Markdown 初稿；最终 PDF 与初稿的一致性需要人工核对并在 submission.json 的证据中说明。

## 反防御性修订

先分类，再修改：空泛免责声明、必要范围、真实局限、概念区分、证据限定、重复解释。

| 原表达或问题 | 修改方式 |
| --- | --- |
| “虽然取得了一定成果，但仍存在诸多不足。” | 删空话；写出具体发现与实际未验证条件 |
| “本文并不声称在所有场景有效。” | 写“本文评估了 A/B 条件；C 条件尚待验证” |
| “由于资源有限，结论应谨慎看待。” | 交代实际规模、重复次数和对应结论范围 |
| “这可能在某种程度上提高性能。” | 用真实效果大小与不确定性说明；没有数值则不编造 |
| “换了一个模块，但写成全新理论。” | 如实说明来源、修改与新增证据，不用故事掩盖复用 |

删除没有信息量的道歉、重复退让和自我交代。保留真实局限、影响结论的假设、数据使用限制和证据不足的限定。不能把相关改为因果、把初步改为确定，或把负结果藏起来。

换模型修订可以帮助发现习惯用语，但不能保证准确。给修订者同时提供原文、主张账本与相关证据；要求保留事实、数值、引用和限制，输出修改理由及待验证之处。最后由作者回查，不凭“更流畅”验收。

## 投稿前检查

查当年官方 CFP、author instructions、template、AI 使用政策及补充材料要求，记录精确 URL 和日期。不要把往年页数、模型规模猜测或网络视频说法当成规则。

submission.json 包含 venue/year/track、核查日期、最终 PDF 和全部包内文件。每项核查附实际文件：

- 格式、页数、字体、图表、链接与引用。
- 匿名性：正文、附录、PDF 元信息、代码路径、仓库链接与压缩包内容。
- 文献真实可查，转述与原文一致，方法来源完整。
- 当前 AI 政策、作者责任和必要披露。
- 数据、代码、伦理与隐私要求；根据研究真实适用项处理。
- 复现环境、命令、配置、数据版本与原始/派生指标对应。
- 渲染最终 PDF，逐页核对可读性、溢出、裁切及正文与成果的一致性，保存检查记录与预览图。

与最终 PDF 一致的补充材料和复现包全部准备完成后，才处理用户授权范围内的上传和提交。工具不访问投稿账号，也不宣称已投稿；检查通过不等于论文被接收。

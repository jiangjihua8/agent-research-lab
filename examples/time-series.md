# 待验证计划示例：非平稳条件下的时间序列预测

这是研究设计示意，尚未检索文献、运行实验或证明新颖性。不要直接作为论文贡献或实测结论使用。

## 从方向收敛到问题

宽泛方向：“用 AI 找一个时间序列模块。”

可检验的问题：“在时间顺序切分且可用历史相同的条件下，某个已跑通基线在分布漂移阶段的误差为何上升？它是否依赖失效的归一化统计？”

第一步让 Agent 检查已有数据与代码、复现实验、定位分段误差；如果没有实际失效，就不能假定这个故事成立。检索非平稳性、归一化、分布漂移和已知反例，并核对是否早有相同干预。

## 一个候选假设

| 项目 | 待验证内容 |
| --- | --- |
| 现象 | 基线在定义好的漂移条件下发生可重复误差上升 |
| 机制假设 | 可用历史的统计估计不适配当前分布，而不只是模型容量不足 |
| 最小干预 | 调整统计估计方式，尽量保持预测主干与训练设置 |
| 预测 | 在特定漂移强度下误差与统计偏差共同改善；稳定阶段不一定获益 |
| 替代解释 | 增加参数、改变学习率、泄漏未来信息、数据选择偏差 |
| 反证 | 在排除替代解释后预测仍不成立，或合理重调原基线即可获得同样收益 |
| 创新核查 | 与最接近的归一化和适应工作逐项比较机制、使用信息、成本和新证据 |

## 先搭地基

确认窗口与标签时间戳、预处理拟合范围、未来协变量可用性和测试集隔离。核对指标的归一化空间、反归一化及聚合口径。用手算样例验证指标，短测验证实现，再复现相关强基线。

若需要新实验，比较原基线、干预、容量控制和机制消融。具体数据、规模、种子和预算由实际资源与预期方差决定，不能从本示例推定。先在 validation 选择超参，再做冻结的正式评测。

## 允许的结果

可能支持机制，也可能发现强基线调参后收益消失，或原评测存在泄漏。后两类结果也要完整保存。只有证据足够时才形成论文主张；不因已经想好标题而隐藏负结果。
